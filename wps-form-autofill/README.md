# WPS 表单 / 金山表单 自动填写助手（Tampermonkey 油猴脚本）

打开表单页 → 题目一渲染出来 → 自动把你预先配置好的答案填进去（含单选、多选、下拉、分页表单），
并且**逐字段回读校验**：填不进去会明确告诉你是哪道题、为什么失败，而不是"看起来填上了、提交却是空的"。

```
wps-form-autofill/
├── wps-form-autofill.user.js     ← 油猴脚本本体（直接安装这个文件）
├── demo/ksform/index.html        ← 可交互演示页（复刻 WPS 表单结构，含"表单内部状态"面板）
├── tests/run-tests.mjs           ← 单元 + React 受控组件模拟测试（116 条断言）
├── tests/demo-smoke.mjs          ← 端到端测试：真实 HTTP 加载演示页并验证填表结果（18 条断言）
└── package.json                  ← npm test 一键跑全部测试
```

## 1. 快速开始

1. 浏览器安装 **Tampermonkey**（油猴）扩展。
2. 打开 `wps-form-autofill.user.js`，Tampermonkey 会自动识别文件头 →
   点击"安装 / 更新"（也可以在扩展里"添加新脚本"，把内容整段粘贴进去）。
3. 打开目标表单（形如 `https://f.kdocs.cn/ksform/w/write/xxxx` 或 `/ksform/xxxx`）。
4. 右下角出现 **「WPS 表单自动填写」** 面板：
   - 在「我的信息」里填一次姓名 / 学号 / 性别 / 选题…（只存在你本地，见第 7 节）；
   - 点「保存配置」，之后**所有**表单都复用这套信息；
   - 打开表单时会自动填充；没自动填时可以点「一键填写」，或右键油猴图标 →「① 立即填写当前表单」。
5. 想确认脚本在当前页面能不能用？点面板里的 **「兼容性自检」**（第 5 节）。

> **只填不提交**：`autoSubmit` 默认关闭。脚本填完会停在表单上，由你自己检查并点击提交。
> 打开"自动提交"后，脚本也只会在**所有必填项都校验通过**时才点提交，并且会先弹确认框（可再点"确定"前取消）。

## 2. 它到底解决了什么问题（核心机制）

WPS 表单是 React 应用，输入框都是**受控组件**。对受控输入框执行：

```js
input.value = '张三';                                  // ❌ 看起来填上了
input.dispatchEvent(new Event('input', { bubbles: true }));  // ❌ 这样也没用
```

React 在节点上装了一个 `_valueTracker`（值跟踪器）来记录"我上次看到的 DOM 值"。
`input.value = x` 走的是节点上被 React 打补丁过的 setter，它会**顺手把 tracker 也同步成新值**，
于是 React 收到 `input` 事件时一比对 —— "DOM 和 tracker 一样，值没变" —— `onChange` 压根不会触发，
表单内部状态仍是空的，提交上去自然就是空值（这就是"明明填了却提示未填写"的根因）。

脚本的做法（第 3 节 `nativeValueSetter` / `setViaProtoSetter`）：

```js
const setter = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set; // 原型上的原生 setter
setter.call(input, '张三');                                  // 绕过节点补丁 → tracker 保持旧值
input.dispatchEvent(new InputEvent('input', { bubbles: true, inputType: 'insertText' })); // React 这才认为真的变了
input.dispatchEvent(new Event('change', { bubbles: true }));
// 再回读 input.value 做校验；不一致就换下一种策略（tracker 重置 / 逐字符键盘模拟）
```

演示页右下角有个**对照实验**按钮：点「❌ 直接 input.value 赋值」→ 右侧"表单内部状态"不会变；
点「✅ 脚本的写入方式」→ 状态立刻同步。可以直观看到两者差别。

其他几件必须处理好的事：

| 场景 | 处理方式 |
| --- | --- |
| 单选 / 多选 | 不用 `checked = true`，而是**点击真实的 label/input**（很多组件只监听 click），再回读"选中项文字"校验 |
| 下拉选择 | 浮层通常挂在 `body` 的 portal 里，不在题目容器内：先点触发器 → 在全文档范围找"点击后新出现的浮层" → 点匹配的选项 → 回读触发器文本 |
| "其他"自定义项 | 自动点开"其他/自定义"→ 找到新出现的输入框 → 写入并回车 |
| 分页表单 | 填完当前页 → 严格白名单匹配「下一页/下一步」（**永远不会匹配到「提交」**）→ 等题目签名变化确认翻页成功 |
| 选项文字不完全一致 | 匹配顺序：归一化精确 → 序号（`3` / `第三项`）→ 长度相近的互相包含（近似匹配会标注出来）→ `custom:自定义内容` |
| 多道"志愿/选题"题 | 按题干序号（"第二志愿"）或它在**整份表单（含隐藏分页）**中的位置定位到 `选题/志愿 1|2|3`，绝不把第一志愿的内容填到第二志愿上 |

## 3. 页面识别策略（为什么不依赖 class）

你贴过来的 HTML 里，表单页面的关键结构（题目、选项）是 **React 运行时渲染**的，源码里看不到；
而且 WPS 表单的构建产物 class 名带哈希（`css/3119.6231a7c.css` 这类），**每次发版都可能变**。
所以脚本的第一原则是：**不硬编码 class**。

识别分三层，逐层降级：

1. **语义/无障碍层（主用）**：`input` / `textarea` / `select` / `[role=radio]` / `[role=checkbox]` /
   `[role=combobox]` / `[aria-haspopup=listbox]` / `[contenteditable]` / `[aria-required]` / `<label for>`。
   这些是 WPS 表单为了可访问性和组件库（antd 系）而必须保留的，改版也不会动。
2. **结构线索层（辅助）**：`[data-question-id]`、`.k-form-item`、`[class*=form-item]`、`[class*=label]`、
   `[class*=select]` 等，只作为"加速定位"的线索；命中失败会自动跳过，不影响正确性。
3. **兜底反推层**：如果一道题都没识别到（class 全变），就**从控件反推题目容器** ——
   向上找到"控件数量刚好等于本题应有数量、且第一行文字是短标题"的最近祖先。

题干取值也做了容错：优先取 `label/title` 元素，其次取容器第一行文本，最后兜底用控件的 `aria-label`；
并统一归一化（去空白、去 `*`、去 `（必填）`、去 `1.` 序号、去全角标点）后再和字段字典匹配。

**题目匹配**用的是"字典 + 打分 + 语境规则"：`姓名`、`学号`、`学院`、`手机号`、`指导教师`、`选题/第一志愿`…
（完整字典见脚本里的 `ALIASES`）。语境规则用于避免误判，例如：
题面含"指导/导师"时不会把"指导教师姓名"当成选题；"学院"不会抢"专业/班级"的题；"是否服从调剂"只在题面确实含"调剂/服从"时才匹配。

> ⚠️ 关于域名白名单：脚本 `@match` 覆盖 `*.kdocs.cn / kdocs.cn / *.kdocs.com / *.wps.cn / *.wps.com / localhost / 127.0.0.1 / file://`。
> 如果你把表单部署到自己的域名，可在页面里加一句 `window.__WPS_AUTOFILL_FORCE__ = true;` 强制启用（演示页就是这么做的）。

## 4. 配置项

### 4.1 「我的信息」（全局，所有表单共用）

`姓名` `学号` `班级` `专业` `学院` `年级` `手机号` `邮箱` `性别` `宿舍号` `指导教师`
`选题/题目`（= 第一志愿）`选题2（备选）` `选题3` `备注` `服从调剂`

下拉题填**选项文字**即可（如 `数字媒体技术`）；也可以填**序号**（`3`、`第三项`）；
选项里没有的可写 `custom:你的内容` 走"其他"自定义项。多选/多选用顿号或逗号分隔：`人工智能、数字媒体技术`。

### 4.2 每个表单的「覆盖值」

面板下方"本表单结果 / 覆盖值"列表里，每道题右侧都有一个输入框：
填了就**只对这份表单生效**（优先于全局信息），留空则忽略。适合"这份表单选的是 A 题、那份表选 B 题"的场景。
清空入口：油猴菜单 →「④ 清空本表单覆盖值」。

### 4.3 行为设置

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 开启脚本 | ✅ | 总开关 |
| 自动填写 | ✅ | 题目一出现就自动填（含 SPA 路由切换、分页切换、从后台切回） |
| 覆盖已填内容 | ⬜ | **默认只填空字段**，不覆盖你已经改过的答案 |
| 自动点"下一页" | ✅ | 本页必填项没填完时**不会**翻页 |
| 模拟真人延迟 | ✅ | 字段间随机 70~190ms，降低误判/风控风险 |
| ⚠️ 自动提交 | ⬜ | 全部必填通过后延迟 1.5s 点提交，并处理确认弹窗；**默认关闭** |
| 控制台调试日志 | ⬜ | 打开后控制台按 `[WPS-AutoFill]` 前缀输出详细过程 |

## 5. 兼容性自检（脚本内置）

面板点「兼容性自检」，或菜单「③ 兼容性自检（含真实写入测试）」，会逐项体检并给出结论：

| 检查项 | 判定内容 |
| --- | --- |
| 运行环境 | 是否在油猴环境（`GM_getValue` 可用否 → 决定配置存 GM 还是 localStorage） |
| 页面匹配 | 域名 / 路由 / DOM 三个判据分别是什么结果 |
| 文档状态、表单根节点 | `#root` 是否已渲染（React 挂载点） |
| 页面模式 | 是否在"编辑/设计"模式（创建者视角不能填报） |
| React 受控组件 | 扫描节点，统计 React fiber 节点与 `_valueTracker` 数量（`_valueTracker` 是不可枚举属性，脚本用 `getOwnPropertyNames` 探测） |
| 原生 value setter | 能否在 `HTMLInputElement.prototype` 上取到原生 setter（**这是脚本的核心能力**，取不到会标红） |
| 题目识别 / 题型统计 | 识别到几道题、分别是什么题型 |
| 配置匹配率 | 几道题匹配到了答案，未匹配的是哪些 |
| 浮层探测能力 | 当前可见浮层数量与探测选择器数量 |
| 分页按钮 / 提交按钮 | 是否找到「下一页」「提交」 |
| 自动提交开关 | 是否处于危险配置 |
| 配置持久化 | 读写一次存储，确认配置不会丢 |
| **真实写入测试（深度）** | 在**第一个空文本框**上真的写一次、数 `input`/`change` 事件、然后**把原值还原**，证明"写入 → React 收到变更"这条链路在你当前页面是通的 |
| 逐题明细 | 每道题的题型、来源（全局/覆盖）、选项数、当前是否已有内容、将要写入的值 |

深度检测特意只挑**空的**文本框、且用完立刻还原，不会破坏你已经填好的内容。

### 6.1 单元/模拟测试覆盖什么

`tests/run-tests.mjs` 里的 `reactify()` **按 React 的真实语义**给测试页的输入框装了 `_valueTracker`：

> 直接赋值 → tracker 同步 → React 认为"没变" → 不触发 onChange；
> 绕过 tracker 写入 + input 事件 → React 才收到变更。

于是"脚本有没有真的把值写进 React 表单"是可以**断言**的，而不是靠肉眼。测试覆盖：

1. **纯函数与字段匹配**：归一化、序号解析（`3` / `第2项` / `第三项` / `custom:` / 电话号码不被当序号）、
   选项精确/近似/越界匹配、日期归一化、多值拆分、字段打分与语境规则、跨分页的志愿定位、题目识别与题型判定。
2. **受控输入写入**：先给出反例（直接赋值 → `updates === 0`），再验证脚本写入 → `updates === 1`、
   `input`/`change` 事件计数、`number` 输入、`contenteditable`、只读/禁用字段被明确拒绝并给出原因。
3. **单选 / 多选 / 自定义项**：点击真实 label 后应用层状态被更新；多值多选；"其他"自动展开并填写且走同一套受控写入；
   不存在的选项给出清晰错误；默认不覆盖已有答案。
4. **下拉浮层**：portal 浮层按文字/序号选中、触发器文本回读、浮层关闭、失败时列出现有选项。
5. **分页与提交安全边界**：全部必填有答案 → 自动翻页并填完第二页；**默认绝不点提交、绝不点"保存草稿"这类无关按钮**；
   有必填项没答案 → 不翻页并在汇总里报告；显式打开 `autoSubmit` → 点提交并处理确认弹窗；单页表单优雅结束。
6. **自检**：内置自检自身也被测试（15 项检查、真实写入测试、还原原值）。
7. **门控 / 面板 / 端到端**：非目标站点保持静默不挂面板；目标站点自动挂面板并自动填充；
   面板改信息→保存→"一键填写"生效；油猴菜单命令注册；每表单覆盖值优先；无 class 线索的"野"表单靠控件反推也能识别。

### 6.2 测试过程中发现并修掉的真实缺陷

这些不是"写测试意思一下"，而是测试真的抓出来的问题（都已修复并有回归断言）：

| # | 问题 | 后果 | 修复 |
| --- | --- | --- | --- |
| 1 | 分页表单里被 `display:none` 藏起来的其它页题目也算作"可见" | 在只渲染一页的表单上会去填看不到的字段、必填校验误判 | `isVisible()` 增加祖先链检查（无排版引擎时）/几何尺寸判定（浏览器里） |
| 2 | 从控件反推题目时一路爬到公共父级 | 两道题被合并成一道，只认出 1 道 | 容器必须"控件数不超过本题应有数量"；同时加"最近候选"弱判据避免漏识别 |
| 3 | 近似匹配过宽 | 16 字的"其他"自定义内容被硬凑到 4 字选项上，没走自定义输入框 | 近似匹配加长度比例窗口（0.45~2.2） |
| 4 | React 探测用 `Object.keys` | `_valueTracker` 是 `defineProperty` 挂的、不可枚举 → 误报"没检测到 React" | 改用 `Object.getOwnPropertyNames` |
| 5 | 题目族按"本次调用顺序"分配 | **分页表单第二页的"第二志愿"被填成第一志愿的内容** | 改为按题干序号 + 在整份表单（含隐藏分页）中的位置定位 |
| 6 | 只读 / 禁用控件会被"写成功" | 虚假的成功提示 | 填充引擎明确拒绝并说明原因 |
| 7 | 用户手动改动后脚本又自动填回去 | 打扰用户 | 真实输入后 60 秒内自动填充让路 |
| 8 | 演示页的 tracker 模拟与 React 语义不一致 | 演示"看起来"直接赋值也能更新状态，误导 | 把 tracker 与表单状态拆成两个变量，严格对齐 React |

### 6.3 关于"真机验证"的诚实说明

本仓库的沙箱**无法访问 f.kdocs.cn / kdocs 域名**（外网受限，且表单通常需要登录），
所以我没法替你在真实页面上跑一遍。脚本因此刻意做了两件事：

1. **不依赖任何 class**（第 3 节），改版不会直接让它失效；
2. **自带兼容性自检**，其中"深度检测"会在**你所在的真实页面上**做一次真实的"写入 → 事件 → 还原"闭环验证，
   一眼就能看出这条链路在真实 WPS 表单里是否可用。

如果你在真实表单上跑，最可能出现的两种"半失败"以及处理方式：

- 自检里 **"配置匹配率"** 有题目没匹配上 → 那就是字段字典没覆盖到该题面：
  在面板里用该题的**覆盖值**输入框直接指定（列表左侧会显示识别到的题干），或把题面发我，我把别名加进 `ALIASES`。
- **下拉/日期题**失败 → 自检的"浮层探测能力"和失败详情里会列出捕获到的浮层与选项文字，
  把那段日志发我即可精准修（不同组件版本浮层 class 可能不同）。

## 7. 安全、隐私与边界

- **所有配置只存在你本地**：油猴环境下用 `GM_getValue/GM_setValue`（每台机器独立），
  非油猴环境下退化为 `localStorage`。脚本**不向任何服务器发送数据**，也没有任何外部请求。
- **默认不提交**：`autoSubmit` 默认关闭；"下一页"用严格白名单匹配，永远不会匹配到「提交」；
  绝不去点"保存草稿/清除/取消/返回"这类按钮（有专门的断言守着）。
- **默认不覆盖**：只填空字段。想强制覆盖（含清空后重填）再打开"覆盖已填内容"。
- **自检不污染表单**：深度写入测试只挑空的文本框，并且立即还原原值。
- **不处理的内容**（明确不管，避免帮倒忙）：
  - 文件上传题、定位/坐标题、图片题（脚本会标记为不支持并跳过）；
  - 验证码、短信验证、滑块、登录/授权流程（请手动完成，脚本只负责题目）；
  - 富文本编辑器里的复杂格式（只写入纯文本）；
  - 级联选择（省/市/区两级以上）、复杂日期区间（脚本会尝试打开浮层并匹配文字，失败会明确报错）；
  - `cross-origin iframe` 里的表单（浏览器同源策略限制，任何油猴脚本都碰不到）。
- **合规提醒**：请只在你**有权填写**的表单上使用，并遵守表单发布方的要求；
  自动提交可能造成不可撤销的后果，脚本默认不开启是刻意的。

## 8. 常见问题

**Q：自检全绿，但还是提示"XX 未填写"？**
A：看"逐题明细"里该题的"当前值"和"将要写入的值"。若该题状态是"已有内容"而你其实没填，
说明它是个非受控输入或被其它组件接管了 —— 把明细发我，我按真实 DOM 适配。

**Q：手机端的 WPS 表单能用吗？**
A：脚本没有依赖桌面特有 API（用的是 pointer/mouse/keyboard 事件与 `InputEvent`），
在 Tampermonkey 支持的移动端浏览器（如 Kiwi、Firefox for Android）上通常可用，但没有真机验证过。

**Q：会自动帮我"抢"名额/秒填提交吗？**
A：脚本能在页面渲染完的第一时间填好（`document-start` 注入 + MutationObserver + 多路触发），
但**默认不会替你提交**；是否开启自动提交、以及是否用它去抢，请自己判断合规性。

**Q：我在面板里保存的信息会不会被别的脚本读到？**
A：会 —— `GM_getValue` / `localStorage` 对本机所有脚本都是可读的。请不要在这样的配置里放密码等敏感信息。
